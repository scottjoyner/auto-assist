\begin{abstract}
We examine Mercury Bots as specialist execution workers behind a separate provider-quota authority. A Python fixture-only adapter implements three bounded roles, synthetic lease checks, and a locally chained audit journal. Forty offline tests pass. These tests establish only local behavior; they do not establish genuine model output quality, upstream budget safety, multi-host coordination, or immutable custody.
\end{abstract}

\section{Motivation}
One physical provider allocation may appear behind multiple free-token aggregators, and alias names cannot prove independent entitlements. The fleet must separate provider authorization from specialization. Mercury Bots support persistent personas, delegated queues and delivery paths \cite{mercury}, but their job leases and local token counters are not a shared upstream quota coordinator.

\section{Predictions and experimental method}
The fleet's knowledge PR~51 recorded broad acceptability gates before this slice. The detailed unit assertions were refined during implementation and therefore do not constitute separate, independent preregistration. We predict disabled/missing admission rejects dispatch (P1); unknown roles or models reject (P2); revoked leases and provider errors stop simulated events (P3); bounded budgets and finish evidence gate completion (P4); and a failed or modified journal prevents new work (P5). Mock completion must never imply verified useful work or provider credits (P6).

Only \texttt{FixtureWorker} is executable, with provider and model fixed to a synthetic namespace. The mock authority grants/renews leases before each event is consumed, and records terminal release. The journal stores task and objective digests \cite{nist}, state transitions, bounded token usage and a previous/current hash pair. It does not include raw prompts or tool outputs and is not an independent WORM record.

\section{Results}
The focused Python suite passed 40 offline tests in 0.32 seconds; syntax compilation and Git whitespace checks also succeeded. There were zero provider-generation calls because no live transport exists in this module. The tests cover mock denial, synthetic provider errors (401, 402, 403, 429, 503), renewal loss, exact model identity, budget checks, duplicate task IDs, chain tampering, and journal read/write denial. HTTP 429 is not proof of paid/free allocation exhaustion \cite{rfc6585}. No independent quality scoring, Mercury runtime invocation, cross-node contention or off-host custody was performed.

\section{Threats and next gate}
The injected authority is not authenticated, the journal remains locally mutable, and the synthetic worker cannot prove streaming cancellation in a real LLM SDK. Mercury's webhook ingress enqueues without our production upstream lease; no webhook or daemon was activated. The next study must place an authenticated admission gate at the actual provider-call boundary in a pinned Mercury integration, and test lease-loss and storage-custody failures under a no-generation mock transport before any live free-provider authorization.
