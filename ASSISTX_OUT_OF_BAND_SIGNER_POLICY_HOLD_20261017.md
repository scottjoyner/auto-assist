## Implemented

- scripts/verify_signed_builder_policy.py validates a supplied
  operator-root Ed25519 DSSE authorization envelope and a distinct
  builder Ed25519 SLSA/in-toto DSSE statement.
- Operator and builder raw public keys MUST differ. Root signature
  has its own domain-separated content type. A separately expected
  root SHA256 fingerprint is required; keyid is not authority.
- The signed policy scopes an exact service, source Git commit,
  immutable manifest SHA256, builder identity, build type and
  authorized builder public-key SHA256; bounded epoch and signed
  not-before/expiry (maximum 24-hour authorization). Unknown fields,
  scope changes and signature mismatches are denied.
- The independently supplied expected policy epoch must match.
  This rejects a replayed old policy ONLY if the external witness
  has been advanced; the code does NOT provide a non-restorable
  externally governed epoch witness.
- Supplied revoked fingerprints are denied, but the code DOES NOT
  prove the revocation snapshot is fresh, authenticated or
  independently witnessed. The local clock is not trusted time.
- Only after checking the root policy does it call PR409's
  strict source/manifest/runtime DSSE verifier. Even two
  cryptographically valid signatures return promotion_authorized=false,
  production_decision=HOLD, with independent root custody, trustworthy
  clock, fresh revocation and non-restorable epoch all unproven.
- No production Docker, database, network, model, credential or
  effects are changed by either verifier or the stage.
