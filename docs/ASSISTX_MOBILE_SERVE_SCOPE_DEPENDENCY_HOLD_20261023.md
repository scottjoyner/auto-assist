# Mobile SSO dependency: preserve Tailscale Serve 8443 while replacing raw ingress 8000
**2026-10-23 | PR #425 | P0 #414 | live cutover HOLD**

Fleet Commander inspected two **different** ingress paths on x1-370: raw user-systemd `socat` listens at Tailnet IPv4 port 8000 (still active **and enabled at boot**) and Tailscale Serve HTTPS port 8443 proxies five specific mobile API paths directly to `127.0.0.1:8000`. The latter injects the verified Tailnet identity through its separate Serve boundary, used by the mobile auth code. It must not be replaced by the raw-port sanitizer or have unrelated Serve mounts reset.

The **exact allowed Serve API mounts** are `/health`, `/api/v1/auth/whoami`, `/api/v1/runtime/catalog`, `/api/v1/agent/chat/completions` and `/api/v1/model/chat/completions`. Their backend targets are the exact corresponding loopback paths. The 8443 root and `/relay/signals` belong to other services; root mounts on 8445, 8446, 8448 and 8449 are unrelated.

Read-only live checks returned HTTP 200 on `/api/v1/auth/whoami` from both Lenovo and x1-370; only `authenticated=true` and `provider=tailscale` booleans were reported (no login, response contents, or session identifiers disclosed). Production `TRUSTED_AUTH_HEADER` is canonical. Although `KIPNERTER_TAILNET_ALLOWED_LOGINS` is empty in the container environment, a **non-empty, nonsymlink mounted fallback allowlist exists**; the guard does not enumerate it or rely on its content. Basic API localhost health remains HTTP 200.

New opt-in `scripts/assistx_mobile_serve_scope_guard.py --physical-readonly` inventories these exact Serve bindings, disallows wider direct AssistX mounts or other host/port mappings, and reports HOLD regardless of route match. It neither issues client requests nor mutates Serve. The default invocation does nothing. **15 guard unit tests passed**, including missing, redirected, unknown, wrong-host, and wider mounts; **153 combined related sanitizer tests passed** (one existing Starlette deprecation warning), Ruff clean.

**Release consequence:** the backend trusted-header authentication setting and Serve/mobile SSO behavior must be qualified separately from sanitizing raw TCP port 8000. Blanket rejection of legacy trusted headers might change mobile auth behavior and is *not* approved by this evidence. Do not reset Tailscale Serve or treat a successful Caddy loopback rehearsal as a production replacement. The real socat boot-enabled bypass still exists. Keep PR #425 draft, issue #414 open and production cutover HOLD until the original service is retired from startup and a reviewed sanitizer-only fail-closed replacement is proven on the actual port with genuine client acceptance.
