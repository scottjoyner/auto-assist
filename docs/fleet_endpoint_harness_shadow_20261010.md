# Fleet endpoint harness — offline shadow acceptance (2026-10-10)

**Implementation**: `src/assistx/fleet_endpoint_harness.py`, `scripts/fleet_endpoint_harness.py`, `scripts/fleet_endpoint_snapshot.py`.
**Mode**: offline/read-only. No discovery sockets, API requests, generation, provider login, model load, route changes, or timer installation.
**Authority**: zero production admissions. Local receipt PASS is not billing, archive, signed runtime admission, or answer-quality proof.

## Placement / fitness

| Fleet role | Proposed placement | Evidence source | Dispatch policy |
|---|---|---|---|
| Passive catalog reporter | x1-370 existing `fleet-provider-presence.timer` | Local JSON provider snapshot | No dispatch |

| Durable archive target | Beelink NAS5 after storage approval | SHA-256 copy + independent restore witness | No copy/delete in this iteration |
| Physical mobile acceptance | Mac build device + connected iPhone | Exact-head build/render/auth proof | Separate iOS release gate |

**Cloud free-model rules:** exact provider and model; no `auto`/`free` routing alias, unknown upstream alias groups remain unknown. Even a fresh catalog + locally checked trace never grants another quota lease. An upstream 429/503/403 remains an explicit deny/cooldown in the existing guarded launcher, not a reason for paid fallback.

**Local rules:** online machine, loaded model, health and props are different facts. An embedding model must never be advertised as chat. Local observation files remain untrusted snapshots, even when they contain `canary_pass:true`; production admission still requires authenticated observer, signed projection and real completion quality evidence.

## Source contracts

- `config/fleet-endpoint-inventory.example.json`: *illustrative* candidate inventory; its three `example-*` records are not deployed hosts or actual loaded models.
- Provider metadata: private `provider-presence/v1` generated by the already-installed passive collector. `catalog_reachable` is informational.
- Guarded free tasks: manifests from `subagents/manifests/<session-id>.json` and JSONL from the sibling `traces/`. Run is locally verified only if completed, exact resolved model, provider-reported zero cost, session-linked nonempty text, terminal stop, and actual trace bytes matching SHA-256.
- Optional local observations: `fleet-local-observations/v1` with `endpoint_id`, `model`, `model_kind`, `observed_epoch`, `health`, `loaded`, `props_confirmed`, `canary_pass`. Untrusted until observer authentication and signed runtime projection.
- Report: `fleet-endpoint-harness-report/v1`; all entries `production_admitted=false`, `automatic_dispatch_allowed=false`. Redacts full endpoints, prompts, credentials and trace contents; retains model, status, session ID and manifest digest only.
- Private snapshot: receipt with report SHA-256 and canonical input-source hashes, mode 0600; integrity checked locally, not independently archived or tamperproof.

## Tailnet SSO identity replay contract — continuation

## October 12: observation response is a non-actionable presentation contract

The opt-in, system-TLS HTTPS self-probe previously accepted `schema_version=1`, `source=tailnet_observational_only` and `authority=not_admitted` as sufficient proof of a structurally valid observations response. That could incorrectly label a HTTP 200 response with `models[*].selectable=true` or `admitted=true` as an observation-only response. The new `fleet_serve_https_probe` validator checks the exact sanitized mobile observation shape, limited model count, non-actionable boolean flags, canonical safe display labels, explicit resident/advertised/installed states, nonnegative counters and the two hex-only source fingerprints. A malformed or actionable response sets `observational_only_schema=false`, `fresh_nonselectable_observations=false` and `observations_state=invalid_contract`.

A structurally valid empty `stale`, `unavailable`, `invalid` or `not_configured` response may retain `observational_only_schema=true` **but cannot** satisfy `fresh_nonselectable_observations`. A fresh response is only a **sanitized presentation**, not proof of the claimed source hash, live producer process, model residency, authenticated Tailnet identity, trusted proxy anti-spoof ingress, provider execution eligibility, or storage custody. This distinction remains true after a 200 response.

The negative contract test suite includes actionable model flags, unsafe host/path strings, invalid state/digest/counter/schema payloads, invalid count limits and stale-with-model anomalies. It uses in-memory transports only: no model requests or provider quota were consumed. The actual observed deployed route on the separate, operator-controlled 8443 Serve listener still requires repeat authenticated physical-device acceptance after #254/#255/#259 rollout.
