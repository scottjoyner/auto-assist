## Threat and smallest isolated implementation

PR #362 verified two Ed25519 signatures **inside** a Neo4j Enterprise 5.26 `WRITE` procedure. A restricted ordinary caller could not directly `SET`, `CREATE` or `DELETE` while the boosted, fixed, signed procedure could mutate a fixture Task. But a graph-only administrator rewind of graph-local `term`, `high_water`, nonce history and Task status reaccepted the **same legitimately signed proof**.

This extension adds a **separate disposable Python witness container** on a second private internal Docker bridge. Its SQLite durable ledger plus separately fsynced checkpoint live entirely outside the Neo4j container/graph store. Its server pins independent public issuer/device roots, verifies **both Ed25519 signatures on the same strict, domain-separated native claim**, checks exact fixture instance, agent, policy digest, operation, term, next sequence, nonce and expiry, and atomically reserves a strictly increasing high-water. Each success stays **PENDING_UNCERTAIN**, permanently blocking a second reservation; there is **no automatic release, retry, reconciliation or failover**.

A third ephemeral Ed25519 witness **private** key stays only in that witness container. The Java Neo4j procedure pins the corresponding **public** root, requires the external witness to answer with a receipt signed over a fresh random-challenge-bound request digest, verifies that signature **within the Neo4j procedure**, and only then advances its graph-local fence and changes one `FixtureTask READY -> CLAIMED` in the original fixed transaction. A direct graph caller is still denied `SET`, `CREATE` and `DELETE`; it may invoke only the narrowly named boosted fixture procedure. Witness URLs are fixed by disposable process environment, **not user arguments**; arbitrary caller-provided Cypher, trust roots and resource URIs cannot be passed to this plan.

**Important:** Graph and witness are two independent resources with **no atomic distributed commit**. The witness is an entirely local container with a writable overlay: its SQLite+checkpoint can be restored together, and an administrator can replace the graph, modify plugin binaries/configuration or suppress legitimate signed writes. Private fixture witness keys and public trust roots are generated by the same test orchestrator, not issued by a real fleet or independently protected by HSM/TPM/quorum. The fixture HTTP channel is internal plain HTTP with a bearer and a signed challenge response, **not production mTLS**.

Each creates uniquely named isolated Docker networks, a new Neo4j 5.26 Enterprise graph with a source-compiled Java plugin, and an independent Python witness. All keys/passwords and data are synthesized in the fixture. Images and Python dependencies are read exclusively from the authorized host's **existing cache**; no network download, persistent graph mount or host-published graph port is used. All fixture containers and bridges are torn down via the runner's `finally`. **Only the disposable graph/ledger/anchor are mutated.**

1. **Normal:** One dual-signed fixed Neo4j claim advances both graph-local and witness-local high-water. A witness **container restart** preserves PENDING. An administrator rewinds **only the fixture graph** to prior term, nonce history and `READY`; the same previously accepted legitimate signatures are **rejected by the independent witness**. Result: `PASS_GRAPH_ONLY_REPLAY_DENIED_PENDING_NO_GO`.
2. **Outage / ambiguous effect:** With the witness container running but deliberately **paused**, a valid native procedure attempt times out and **does not change the graph**. In observed runs, the queued request is processed after the witness resumes: **high-water becomes 1 and PENDING is true even though the graph effect failed**. No automatic retry can be allowed. Result: `PASS_FAIL_CLOSED_UNCERTAIN_NO_AUTO_RETRY`. This is an explicit no-liveness gate, not successful recovery.
3. **Coordinated restoration:** After a successful signed claim, the fixture administrator restores the **graph AND the separate witness SQLite/anchor snapshot** to their pre-claim state, with the **same ephemeral signer roots and instance**. The same previously consumed signed claim is **accepted again**. Result: `PASS_EXPECTED_COHERENT_ROLLBACK_REPLAY_NO_GO`. **This is the critical release blocker**, physically reproduced by a test-only reset inside disposable containers.

## Unresolved promotion requirements — all hard HOLD

- **Independently protected and genuinely non-rollbackable monotonic custody:** a local SQLite+anchor pair is only *separate from the graph*. It can be co-restored, deleted or replaced. Use independently secured quorum/TPM/WORM-like high-water witnesses with pinned device keys, key rotation rules, separation of administrative custody and a verified high-water term protocol; do not silently bootstrap after missing history.
- **Uncertain in-flight reconciliation:** the witness can persist PENDING when the Neo4j transaction never committed (proven). Need independently trusted post-COMMIT receipts and a recovery protocol that can distinguish not-started, pending, committed, and externally visible side effects without double execution, stale terms or unintended release. The present fixture intentionally never finishes/reconciles a pending claim.
- **No privileged bypass:** a Neo4j administrator can still mutate the graph or swap the privileged Java procedure; the witness administrator can co-restore/delete its state or misuse its signing key. The exact threat authority and custody boundary must be independently approved. A native boosted procedure is a powerful attack surface, not a generic security cure.
- **Real provenance:** the test signs synthetic IDs with ephemeral keys. Real Task owner/device identity, recovery policy, revocation, signature lifetime, caller-binding, real clock faults and business authorization remain unproven.
- **Real workloads and isolation:** claims alone were tested in a fixture; heartbeat, complete, idempotent retries and all direct Cypher consumers remain unmigrated. Seven previously observed live non-Neo4j containers still had direct Bolt TCP paths and graph host ports were wildcard-bound at that observation. Actual-image cutover, gateway health, Tailscale/host paths, rollback plan and independent approvals remain outstanding.
