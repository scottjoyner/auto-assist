# AssistX sanitized ingress — read-only post-cutover attestation

**October 23, 2026 | PR #425 | ingress P0 #149 | HOLD**

The old `assistx_tailnet_sanitizer_preflight.py` assumes the original raw `socat` service is still running. It therefore cannot certify the *new* Caddy service even if the live cutover succeeds. The new inert-by-default `scripts/assistx_tailnet_postcutover_attestation.py --physical-readonly` inspects only local metadata after an independently controlled cutover; it never starts, stops, installs or disables systemd units, changes Docker/Tailscale/Serve, reads credentials, or performs API tasks.

It requires the legacy `control-room-ts-proxy.service` to be **inactive and no longer enabled at boot**, and the future `assistx-tailnet-sanitizer.service` to be running and enabled. It checks the Caddy process's actual executable and `--config` invocation against an explicit deployment path, SHA-256 pins both Caddy binary and staged release config, and validates expected localhost/Tailnet port-8000 listener addresses. Critically, it now verifies the **Tailnet socket's `ss -lntpe` UID, positive inode, unique binding, and exact systemd ControlGroup** against the candidate Caddy user service; a socket owned by the old socat unit, a Docker process, or an unknown process must not qualify. The mobile Serve five-route census also checks the verified exact Tailnet DNS hostname, not merely a port-8443 suffix.

The expected future Caddy unit and config are **not installed**. The current live readback is correctly **HOLD**, with `legacy_unit_inactive=false`, `legacy_unit_cannot_start_at_boot=false`, `pinned_caddy_process_verified=false` and `pinned_caddy_config_verified=false`. All legacy API/Hermes/Serve runtime state is unchanged.

The socket ownership check is a **read-only kernel/systemd metadata observation**, not evidence of authenticated remote client acceptance, live header-only spoof denial, boot-cycle persistence, or an activated safe Caddy recovery fallback. Its disposition is **always HOLD** until separate operator-verified proof is attached; even a perfect synthetic input to the assessment function cannot set `production_release_authorized=true`. The main ingress P0 and Hermes custody/mount/signed-identity blockers remain open.

**October 23 additional physical check:** the running Tailnet `:8000` socket was correctly attributed to the original `control-room-ts-proxy.service` cgroup; the same socket was correctly **rejected** when assessed as belonging to the proposed Caddy service. The future Caddy unit/config remain absent, the old socat unit is still boot-enabled, and the attestation still reports **HOLD**. These tests send no production HTTP requests and perform no process or service mutations.
