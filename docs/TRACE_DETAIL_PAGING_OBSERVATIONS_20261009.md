# Observations — bounded trace detail metadata and opt-in preview
**Date:** October 9, 2026 EDT. **Parent:** draft [auto-assist PR #175](https://github.com/scottjoyner/auto-assist/pull/175). **Issue:** [#176](https://github.com/scottjoyner/auto-assist/issues/176). **Prospectus:** `TRACE_DETAIL_PAGING_PROSPECTUS_20261009.md` written before implementation/tests.

## Implemented, not deployed
New `src/assistx/trace_detail_pages.py` implements `get_trace_page()` and `get_trace_payload_preview()`. Two new source-owned routes are added:
- `GET /api/traces/{correlation_id}/timeline?limit=80&cursor=...`: returns up to **100 metadata-only events** in descending `ts_ms, event_id` keyset order, one extra lookahead to indicate further records. `event_type`, `source` and bounded top-level scalar IDs only. No `RETURN t` whole node or `payload_json` projection. Index total/retention completeness explicitly **unknown**, and snapshot immutability/physical node identity explicitly **unverified**.
- `POST /api/traces/{correlation_id}/payload-preview`: explicit request body `{"event_id":"..."}`, verifies membership under the correlation group and returns at most **4,096 characters** of `payload_json` plus truthful truncation; no event ID in the query URL, no passive payload prefetch. Both routes specify `Cache-Control: no-store, private`.

Both routes **default to HTTP 503 / no graph access** unless `ASSISTX_TRACE_DETAIL_PAGING_ENABLED=1` AND the app has installed the injected production auth dependency. Existing operator authentication still applies; anonymous requests return 401 when injected. This is a *research feature flag*, **NOT approval to enable**: physical concurrency and trusted proxy/fairness issues [#148](https://github.com/scottjoyner/auto-assist/issues/148) and [#149](https://github.com/scottjoyner/auto-assist/issues/149) must first pass.

## Predicted versus observed
- **Keyset correctness:** a synthetic **1,001-event equal-timestamp** fixture paged in descending unique event IDs with no duplicate or omission in a stable snapshot. Cursor is versioned, base64url encoded, strictly validated, bounded, checked for duplicate attributes and typed scalar fields. Wrong ordering, duplicate key and ambiguous page boundary fail closed.
- **Payload privacy:** a metadata page projects fixed scalar columns only, defensive returned-column allowlist and per-field limits; synthetic private-marker payload does not enter page output. Preview is separate POST requiring an allowed event ID under the **same** correlation group. Incorrect ownership returned no preview; ambiguous match stopped.
- **Routes/security:** feature disabled and missing auth injection prevented graph access; malformed paths, cursors, page sizes and extra POST body keys rejected; no-store headers checked; source and test code compile.
- **Regression:** **131 Python tests passed**, comprising 29 new paging/security and 102 existing outcome/context/evidence/attestation tests. Existing **25 Node VM workbench tests passed**. A Starlette/TestClient deprecation warning is unrelated.
- **Real Neo4j syntax smoke:** disposable isolated Docker **Neo4j 5.26.26 Enterprise evaluation** (`--network none`, no published ports/bind mounts, 1 CPU / 2,200 MiB). Created **1,001 invented events sharing a timestamp** under one synthetic group; extracted the *actual* candidate Cypher strings and ran `EXPLAIN` plus ordinary synthetic read in the container. Both the metadata pagination and explicit payload-preview query compiled and returned expected synthetic projections. Measured `docker exec cypher-shell` process wall: metadata EXPLAIN **3,600 ms** / query **2,291 ms**; payload-preview EXPLAIN **2,315 ms** / query **2,119 ms**. These numbers include CLI/JVM overhead, **not Neo4j driver p95**, query budgets or operator DB hits. The disconnected test container and anonymous volumes were removed.

## Critical limitations / negative findings
1. **The existing frontend and legacy `GET /api/traces/{correlation_id}` remain unchanged and unbounded.** PR #175's latest-80 DOM cap still fetches every event and its payload. This slice is an **off-by-default backend contract**, NOT the finished migration, not a solved leak or network cap on the deployed UI.
2. Keyset ordering is deterministic **for an unchanged indexed snapshot**. New backfills, missing/duplicate IDs, timestamp changes and concurrent appends are not a signed snapshot; `total_indexed_events=null` and `source_snapshot_immutable=false` reflect this.
3. A 4-second Neo4j transaction timeout applies to each of these reads, but the driver timeout and physical query cancellation under stressed concurrency were **not measured**. Query `LIMIT 101` bounds the response, **not necessarily the upstream matching/sorting DB work**. Physical read fencing #148 remains a hard activation blocker.
4. The synthetic preview contains invented content only. Returning a JSON prefix can be partial and is **not a redaction system** or authoritative full-output archive. Authorization/privacy review must define whether payload previews are permitted at all, including operator role scopes and audit logging; current flag must stay disabled.
5. No production data or history read, service changes, Neo4j production writes, NAS, provider inference, router dispatch, trace collector changes, or UI deployment.

## Next narrow engineering acceptance
Implement a coordinated **client migration** that uses paged server metadata and requests payload preview solely on explicit event disclosure. It must not silently fall back to the legacy unbounded endpoint. Preserve context/evidence chips as `unverified` or explicit `not available in current page` rather than synthesizing total counts. Cover browser keyboard/mobile, 401/403/422/429/503, stale cursor, duplicate equal timestamps, 1,001+ events, retries, reconnect, and per-page physical admission.
Then run operator-approved authenticated multiworker Neo4j 5.26 staging plans/p95 and physical fairness/cancellation, before enabling the rollout flag. Keep full historical source→spool→NAS custody (#117) independent.
